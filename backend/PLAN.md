# SunCraft 后端实施计划

依据《夏遮冬透（SunCraft）典型客厅前后端技术方案》第 2–3 页，交付离线运行的 Python / FastAPI / NumPy 服务。每个阶段独立提交 Git。

| 阶段 | 实施内容 | 验收方式 |
| --- | --- | --- |
| 1 · 契约 | 固定房间宽 5.4 m、进深 6.0 m、高 3.0 m。预设上海/同济、北京、广州、哈尔滨。输入含城市或纬度、立面朝向、窗墙比、挑檐深度、百叶倾角。 | 本计划先于源码提交。接口文档明确默认值、范围、单位及边界行为。 |
| 2 · 模拟 | 提供 GET /api/presets 与 POST /api/simulate。计算二至日真太阳正午高度角、方位角、窗上直射遮挡比例、冬季直射透过比例与射入深度。由同一几何模型生成剖面线段。估算 24 × 24 个等面积地板网格中心的 DF。 | 校验背阳与全遮挡情形、采光矩阵的对称性，以及矩阵阈值计数和返回指标的一致性。 |
| 3 · 寻优 | POST /api/optimize 固定城市、朝向和窗墙比，在约千组挑檐深度与百叶倾角中搜索。只对达标面积比例 ≥ 80% 的组合比较夏季遮挡与冬季得热。返回确定性的帕累托折中、原参数及前后指标。 | 用独立枚举核对支配关系。重放推荐参数必须得到同样指标。不可行时返回原因和最高可达采光达标率。 |
| 4 · 联调 | 提供本地启动命令、请求样例、坐标约定、可重现的接口测试与性能测量方式。 | 在实际 FastAPI 路由上运行测试。分别测量预热后的模拟与寻优耗时，和方案的 50 ms 计算及 100 ms 寻优交互目标对照。 |

## 模型约定

- 太阳方位角从正北顺时针计，南向默认 180°。剖面横轴从窗向室内、纵轴从地面向上，单位为米。
- 使用方案给出的 DF ≥ 2.0% 和达标面积占比 ≥ 80% 两个演示阈值。记录采光简化假设，精度与工程标准认证需要独立校准。
- 方案示例仅用于字段命名。数值由几何和采光模型统一计算，完整保留已全遮挡的初始状态。

## 第二轮 · 演示效率

基线为 `4986370`。先记录含不同滑块位置、不同窗墙比的模拟与寻优基准，再进行以下修改。

1. 普通拖动支持只取读数和剖面，热力图模式仍可取完整的 576 点。寻优可在同一次响应返回推荐设计的绘图数据，减少一次往返。
2. 复用同一窗高的采光基础矩阵及固定候选的采光计算，缓存容量固定。新窗墙比、网格外起点与无可行解都要走通。
3. 在预设接口给出可直接使用的哈尔滨演示起点，保留上海默认参数。
4. 对比优化前后同一批有效输入的完整输出，核对精简结果、合并响应、采光阈值边界和实际响应字节数。分开测量固定窗墙比与持续变化窗墙比的 P50/P95，区分进程内接口和用户网络耗时。

## 第三轮 · 光热舒适综合评分

起点为上游合并提交 `8541321`。依据《夏遮冬透（SunCraft）光热评分系统与前后端设计方案》，本轮交付后端与前端数据契约。

1. 分离物理量与规则。复用 24 × 24 地板网格，补齐采光均匀度、窗地比、冬至满窗直射时数、夏至沙发区直射时数、等效 SHGC 与相对负荷降幅。引入可选百叶收起状态，以便表达真正的无遮阳参照。
2. 建立统一的 35 / 25 / 25 / 15 分、十子项分段线性评分函数。报告返回原始量、显示值、门槛、分值、等级、来源类型及红线提示，给前端提供空间联动键。文档列出方案未规定的插值端点和代理模型参数。
3. 在原采光可行域内，以同一个总分对全部候选及网格外当前设计排序，返回优化前后报告。当前设计已最优时保留它，无可行解时给出原因。
4. 做规则端点、日照几何、无/过度遮阳、枚举最优、模拟重放和兼容性测试，测量单次完整模拟与网格寻优的 P95。在 fork 上单独开分支，向上游 main 提交 PR。
