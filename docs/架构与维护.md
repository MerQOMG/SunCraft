# 架构与维护

## 数据流

`App.tsx` 管理设计参数与连接模式，通过 `hooks/useSimulation.ts` 调用 `api.ts`。本地模式使用 `localEngine.ts`；FastAPI 模式请求后端。场景、指标、评分报告和导出使用对应方案的同一份结果，参数更新时旧结果标记为仅供对照，迟到请求不能覆盖新方案。

`components/Scene.tsx` 负责三维显示，`components/Section.tsx` 负责剖面，`components/AnnualTimeline.tsx` 负责日期预览。家具与窗细节在 `modeling/`，评分界面在 `scoring/`。固定示例与旧接口数据只在 `tests/fixtures/`，不参与生产计算。

## 评分与模型

`backend/suncraft/scoring_engine.py` 是评分规则的拥有方。`backend/export_client_reference.py` 导出 `src/scoring/rules.json` 和 `tests/fixtures/backend-scoring-reference.json`。前端本地计算以 48 组模拟基准和 3 组寻优基准核对后端，包括总分、十项贡献、等级、采光与遮阳指标、参数边界和不可行处理。

上海默认方案（0.40 m 挑檐、0° 百叶、45% 窗墙比）显示 91.1 分；挑檐改为 0 m 后为 94.4 分；1.80 m 挑檐、80° 百叶和 65% 窗墙比为 67.3 分。评分采用冬夏设计工况，日期轴只改变几何预览。解析几何、DF 和相对负荷模型的详细适用范围见后端说明。

## 入口与产物

只保留根目录 `夏遮冬透.html` 作为离线成品。默认浏览器、5175 HTTP 预览和后端同源页面共用它，避免不同入口版本不一致。`npm run build:offline` 更新这个文件；`dist/` 为可再生成的生产构建。

开发服务固定使用前端 5174、后端 8001。Windows 启动器会检查两项服务，并在退出时清理它启动的进程。仅环境检查可运行 `powershell -NoProfile -ExecutionPolicy Bypass -File .\start-dev.ps1 -CheckOnly`。

## 检查

前端有单元、模型对照和浏览器回归；后端有 API、几何、评分与寻优测试。命令见根 README。`npm run format` 与 `format:check` 使用仓库内固定版本的 Prettier。测试不会修改历史资料，浏览器截图与下载只写 `前端文件/test-results/evidence/`。
