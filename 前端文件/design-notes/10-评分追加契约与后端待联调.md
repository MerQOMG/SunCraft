# score_report 追加契约 / 后端待联调

2026-11-25，Asia/Shanghai。以下为前端当前已实现的建议契约，不冒称新PDF给出了全部字段/计算函数。

## 路由保持

- GET /api/presets 不变，仍含城市及DF阈值。
- POST /api/simulate 输入仍是原Parameters；返回原角度、metrics、svg_rays、heatmap_grid，可追加score_report。
- POST /api/optimize 不改形状；before/after的模拟也可追加score_report，动画完成后仍请求当前simulate复核。前端不擅自把旧加权网格当新总分最大化。
- 8秒超时、80ms节流、AbortController/序号拒收、显式错误、后端失败不转mock均保留。

## 类型摘要

```ts
score_report?: {
  total_score: number | null; // 0–100；null待数据
  max_score?: 100;            // 省略按100分制
  grade: string; grade_label: string; // 后端决定，前端不重判等级
  warnings: (string | {id?:string; message:string;
    severity?:'notice'|'warning'; item_keys?:string[]})[];
  methodology_note: string;   // 始终标“后端声明，前端未验证”
  provenance?: 'backend' | 'example'; // 省略按接口报告，不代表实测
  completeness?: 'complete' | 'partial';
  version?: string;
  dimensions: {
    id: string; name: string; weight: number; score: number | null;
    items: {
      key: string; name: string;
      value_display: string; threshold_display: string;
      score: number | null; max_score: number;
      status: 'pass'|'warn'|'fail'|'pending';
      citation: string;
      citation_kind?: 'mandatory'|'reference'|'project'|'unspecified';
      link_target?: 'sofa'|'winter-depth';
    }[];
  }[];
}
```

权重/阈值/条文全部数据驱动；来源分类只是提供方的分类，非前端法律判定。citation_kind省略为unspecified，不解析标准编号猜强制性。常见语义key有有限向后兼容映射；推荐显式link_target，禁止URL/任意对象作为联动指令。

完整四维十项JSON参考`verification/scoring-r1/independent-score-example.json`，**它是固定UI示例，不是后端物理基准或每次simulate的合法评分**。PDF原片段仅夏季一维两项；本适配器允许partial保留总分但标不完整，不编造其余维度。

## 校验/降级

- score_report缺失/null：旧版接口正常，胶囊显示待接入。
- 基础物理非法仍走原请求错误；合法物理+非法score_report：仅评分降级，物理/热力/剖面保留。
- 检查数值有限/范围、唯一id/key、完整贡献之和（允许0.11分浮点/展示舍入容差），不重新执行评分曲线。未提供的子项不能伪装完整报告。
- 对字符串长度、维度/子项数作上限；React转义文本，不渲染后端HTML，不把citation当可执行链接。
- heatmap_grid改为矩形number[][]：2–256行、2–256列、同列数、有限非负。第0行南窗、最后一行北；第0列西、最后一列东。尺寸与数值语义不要求24×24，DF数值2.0仍是2%。

## 未提供、不可前端臆补

1. 10项的完整分段函数/反向指标曲线、组合WWR/SHGC曲线、可适用气候/规范条款、项目目标版本及来源分类。PDF片段不足以唯一实现全套真实计分。
2. 四个新增物理计算：全天满窗日照、沙发暴露、均匀度、等效SHGC/负荷碳的完整输入与边界、验证算例、物理结果版本。前端不从现有正午结果推造。
3. ±10%误差验证数据不存在；grade S保证、20ms计算、100ms响应、60fps均未验证。
4. optimize是否真最大化score_report.total_score，以及固定城市/窗墙比约束下可达的最优分数：由后端实现与返回，不能许诺S级。
5. 自动推荐优化的触发元数据（而非在组件硬编码85）、采样时刻/时区、气候区、规范强制/参考适用范围及条文引用、输入快照ID/计算版本建议后端补齐。
6. API是否将额外物理原值放metrics中尚未确定；当前前端只需可信score_report中的value_display，不要求增加虚构物理字段。关联剖面始终使用原svg_rays.winter_hit_depth，与独立示例分开。
