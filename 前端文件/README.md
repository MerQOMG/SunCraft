需要 Node.js 22.12+ 或 24 LTS。项目提供便携 Node 路径识别，不写系统 PATH，不做系统级安装。

```powershell
cd 'D:\大学\大一上\程序设计\智慧空间'
.\start-dev.cmd
# 或 Node 可用时：
npm ci
npm run dev
```

当前源码开发入口打开 **http://127.0.0.1:5174**，仅监听本机。端口占用时 Vite 直接报错，不擅自换端口。

- `start-dev.cmd`：临时将 `.tools/node-v24.22.3-win-x64` 加入当前进程 PATH；首次执行 `npm ci`。
- `start-preview.cmd`：用 Node 内置 HTTP 模块预览 `dist`，不需要 npm 依赖；仅监听 127.0.0.1:5173。

- Ctrl+C 停止开发/预览服务。未部署公网、未创建远程仓库。

## 数据与正确性边界（重要）

当前HTTP源码入口默认 `api`（同源代理）；`file:`离线默认或显式选择 `mock` 时，界面、设计单均注明 **演示 / 近似数据**。模型是仅用于连通交互的可重复启发式函数，不是后端物理算法，不是 GB 50033 判定，不保证 80% 采光面积、真实帕累托最优、100 ms 或 60 fps。演示搜索使用加权网格评分，会保留不达标结果的真实标记，不硬造合格值。

3D 与剖面共用太阳时正午的太阳方向：X 分量严格为 0；已同步结果存在时使用其高度角，等待时用纬度/±23.44° 赤纬解析值。广州夏至正午太阳位于北侧，不伪装成南窗直射。按用户偏好仅保留分析全景，剖去可见屋顶/部分墙，但保留不可见投影遮挡体，不会把剖切误表现为敞顶采光。指标与 DF 仍是原有返回结果，未通过物理引擎校准。默认太阳高度角按 31.2°N 算得约 82.24°/35.36°。**“夏至正午、0.4 m 挑檐、阳光深入沙发区”与高太阳高度及室内固定尺度并不自然一致**；未为满足叙事而伪造低角度夏季太阳或虚构光斑。后续应由后端与小组确认演示时刻/几何或调整叙事。

SVG 射线保持标注高度角，绘制挑檐的几何遮挡边界，百叶细部遮挡以 3D 为准。后端/演示 `winter_hit_depth` 单独用水平虚线展示，绝不把射线拉向该折减深度而改变角度；`summer_blocked` 保留为结果判读文字。SVG 光线是示意，不是施工定位；3D 家具南北位置与示意剖面的物件排布不作为一一精确剖切。热力贴图中的数值是 DF 百分点（`2.0` 表示 2%，不是 0.02）。热力图不随季节切换重新计算，因为当前 API 返回一个采光矩阵；采光因子本来也不等同直射阳光。

## API 联调

复制 `.env.example` 为 `.env.local`（不含密钥），设置后重启 Vite：

```dotenv
VITE_DATA_MODE=api
VITE_API_BASE_URL=http://127.0.0.1:8000
```

也可右上角连接设置临时切换模式/基址；只对当前会话有效。**切换 API 后失败不会回退到演示成功**。后端需允许前端来源的 CORS（当前源码开发 `http://127.0.0.1:5174`；同源代理无需跨域，也要考虑用户自行改用 `localhost`）。建议无鉴权的课程本地接口，不要把私密凭证写入 VITE 环境变量。

以下为“建议契约”，不代表 PDF 已规定缺失字段。需要后端确认后只在 `src/api.ts` / `src/model.ts` 集中适配。

### GET /api/presets

```json
{"cities":[{"id":"shanghai","name":"上海 / 同济","latitude":31.2},{"id":"beijing","name":"北京","latitude":39.9},{"id":"guangzhou","name":"广州","latitude":23.1},{"id":"harbin","name":"哈尔滨","latitude":45.8}],"daylight_threshold_pct":2.0}
```

城市纬度校验当前面向这四个中国城市（23–50°N），增加城市需共同扩展。

### POST /api/simulate

请求（米/度/0–1 比例）：

```json
{"city_id":"shanghai","latitude":31.2,"overhang_depth_m":0.4,"louver_angle_deg":0,"window_wall_ratio":0.45}
```

响应：

```ts
{
 solar_angles: { summer_noon_alt: number, winter_noon_alt: number }, // deg, 0..90
 metrics: {
   summer_shading_rate: number, winter_solar_gain_rate: number,
   daylight_compliance_rate: number, // all 0..1
   is_gb_compliant: boolean, winter_penetration_m: number // 0..6 m
 },
 heatmap_grid: number[][], // rectangular, 2–256 rows/columns, finite nonnegative DF percent-points
 score_report?: ScoreReport, // additive scoring report; see design-notes/10
 svg_rays: { summer_blocked: boolean, winter_hit_depth: number } // 0..6 m
}
```

**坐标约定建议**：房间 X 东向，Z 北向/入室方向，Y 向上；地面中心原点，南窗 `z=-3`，北边 `z=+3`。`heatmap_grid[zRow][xCol]`：第 0 行靠南窗，最后一行靠北；第 0 列在西侧 `x=-2.7`，最后一列在东侧 `x=+2.7`。按实际行列数等分格中心采样；旧演示仍24×24，新后端20×20同样可用。

### POST /api/optimize

请求与 simulate 相同，**city/latitude/WWR 均为约束，不参与寻优**。

```ts
{
 parameters: Parameters, // same request shape; optimal depth and louver only
 before: Simulation,
 after: Simulation
}
```

响应超范围、改变 WWR 或城市、指标非法、热力矩阵错误均拒绝进入 3D。前端滑块建议范围（尚待后端确认）：挑檐 `0..1.8 m / step .05`；百叶 `0..80° / step 1`；WWR `.25...65 / step .01`。固定窗宽 4.4 m，窗高 `5.4×3×WWR/4.4`，垂直居中；房间与家具不缩放。
